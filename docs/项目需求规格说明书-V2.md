> **版本**: V2.0  
> **日期**: 2026-07-02  
> **状态**: 设计中  
> **基于**: `docs/DataAgent Pro V2.0 开发提示词.md` + brainstorming 确认

## 1. 项目定位

DataAgent Pro V2.0 从**单一数据分析模式**升级为**多模式、可配置的智能数据分析与任务处理平台**，融合工作流引擎、通用智能体、RAG 检索增强和动态工具生态，面向企业级数据应用场景。

### V1.0 → V2.0 核心变化

| 维度 | V1.0 (当前) | V2.0 (目标) |
|------|------------|------------|
| 工作模式 | 1 种（数据分析） | 4 种（数据分析 + 研究报告 + 文档智读 + 通用任务） |
| 路由方式 | 固定 13 节点 LangGraph | Body `mode` 参数 + ModeRouter 动态加载 |
| 配置管理 | 静态 `.env` | JSON 文件 + watchdog 热更新 |
| LLM 管理 | 硬编码单模型 | 可视化多模型管理 + 对话中切换 |
| 工具生态 | 内置 Skill 注册表 | 动态 Skill/MCP 管理面板 |
| RAG | 后端检索（无 UI） | 完整知识库管理（上传/切分/向量化/检索） |
| 前端组件 | 纯 CSS | 管理页用 Element Plus，聊天页保持纯 CSS |

## 2. 分阶段递进计划

### 阶段 7：多模式工作流 ⏳

**目标**：将现有「数据分析」模式封装为可插拔的 Mode，新增 3 种模式。

#### 7.1 四种模式定义

| 模式 | mode 值 | 功能描述 | LangGraph 节点链 |
|------|---------|----------|-----------------|
| 数据分析 | `data` | 现有流程：NL→SQL→执行→分析→图表 | clarify_plan→schema→sql→security→execute→quality→analyst→reporter |
| 研究报告 | `report` | RAG 检索知识库 → LLM 生成结构化报告（阶段 7 为纯 RAG，阶段 9 升级为混合） | clarify_plan→rag→report_writer→finish |
| 文档智读 | `doc` | 上传文档 → 向量化存储 → 基于文档问答 | clarify_plan→doc_loader→rag_qa→finish |
| 通用任务 | `task` | 基于 deepagents 的通用 Agent 调度（阶段 10 实现） | clarify_plan→deepagent_executor→finish |

#### 7.2 后端 ModeRouter

```python
# backend/app/graph/mode_router.py
MODE_REGISTRY = {
    "data": get_data_workflow,
    "report": get_report_workflow,
    "doc": get_doc_workflow,
    "task": get_task_workflow,
}

def route(mode: str) -> StateGraph:
    builder = MODE_REGISTRY.get(mode, get_data_workflow)()
    return builder.compile(checkpointer=...)
```

#### 7.3 API 入口（Body 参数分流）

```
POST /api/v1/chat/completions
Body: { "messages": [...], "stream": true, "mode": "data|report|doc|task", "thread_id": "..." }
```

- `mode` 默认 `"data"`，向后兼容当前所有调用
- ModeRouter 根据 `mode` 动态加载对应 LangGraph，复用同一 SSE 流式管道

#### 7.4 前端模式切换 + 联网搜索开关

- 对话框顶部新增模式切换栏（Tab/Pill 样式）+ 联网搜索开关（右侧）
- 4 个模式卡片：📊 数据分析 / 📝 研究报告 / 📖 文档智读 / 🤖 通用任务
- **联网搜索开关**：全局状态，打开后自动在 `tools` 列表中注入 `baidu_search` 工具
- 切换模式时在 SSE 请求中附加 `mode` 字段
- 「文档智读」模式额外显示文件上传区域
- 联网搜索能力跨模式生效：数据分析模式可搜最新行业标准，研究报告可搜最新政策法规，通用任务可搜实时信息

#### 7.5 研究报告模式演进

- **阶段 7**（本期）：纯 RAG — 基于知识库文档检索 + LLM 生成报告
- **阶段 9**（升级）：RAG + 数据查询混合 — 支持 `report_type: "hybrid"`，先 RAG 后查业务数据，LLM 融合

#### 8.5 热更新机制

```
写入 JSON 文件 → watchdog (inotify) 检测变更 → 触发 ConfigManager.reload()
→ 下一次 /api/v1/chat/completions 请求使用新配置 → astream 时 DynamicRegistry 获取最新 LLM / Tools
```

- **零重启**：配置变更后无需重启服务
- **配置校验**：重载时 JSON Schema 验证 + API Key 连通性检测
- **降级兜底**：配置文件损坏时使用上次有效缓存

### 阶段 9：完整 RAG 系统 ⏳

**目标**：构建从前端上传到后端向量化的完整 RAG 流水线。

#### 9.1 前端：知识库管理页

- **文件上传**：Element Plus Upload 组件，支持拖拽上传
- **知识库列表**：Table 展示文件名/大小/切块数/上传时间，支持删除
- **上传进度**：进度条 + 状态提示

#### 9.2 后端处理链

```
用户上传 PDF/docx/md/txt
  → FastAPI 接收文件（POST /api/v1/knowledge/upload）
  → 文件解析：PyPDF / python-docx / markdown
  → 智能切分：RecursiveCharacterTextSplitter (chunk_size=500, overlap=50)
  → 向量化：text-embedding-3-large (OpenAI) 或 bge-m3 (本地)
  → 写入 Milvus Collection
  → 返回处理结果
```

#### 9.3 检索增强生成

- 「文档智读」模式：用户上传文档后立即向量化，基于该文档的 chunk 进行 RAG 问答
- 「研究报告」模式升级：支持 `mode=report&report_type=hybrid`，RAG 检索 + SQL 查询混合
- 检索接口：`POST /api/v1/knowledge/search` — `{ query, knowledge_id, top_k }`

### 阶段 10：通用智能体（deepagents）⏳

**目标**：启用 deepagents 框架（依赖已声明），实现三层记忆 + 定时任务。

#### 10.1 启用 deepagents

```python
# backend/app/agents/deep_agent.py
from deepagents import DeepAgent

agent = DeepAgent(
    model=dynamic_llm,        # 从配置中心动态获取
    tools=dynamic_tools,       # 从 Skill/MCP 注册表动态获取
    memory=memory_layer,       # 三层记忆
)
```

每次 `astream` 通过 `DynamicRegistry` 获取最新 LLM 和 Tools。

#### 10.2 三层记忆

| 层级 | 存储 | 用途 | 生命周期 |
|------|------|------|----------|
| 短期记忆 | Redis List | 当前会话上下文 | 会话结束删除 |
| 长期记忆 | Milvus Vector + MySQL | 历史经验/偏好/知识 | 永久保留 |
| 工作记忆 | 对话上下文 | 当前任务状态 | 单次任务完成清除 |

#### 10.3 定时任务（NL2Cron）

```
用户输入："每天早上 9 点给我发销售日报"
  → clarify_plan 识别为定时任务
  → NL2Cron LLM: "每天早上9点" → "0 9 * * *"
  → APScheduler.add_job(cron="0 9 * * *", fn=execute_agent)
  → 定时触发 DeepAgent 执行 → 结果推送到前端通知
```

## 3. 架构决策记录 (ADR)

### ADR-001：Body 参数分流

**决策**：通过请求 Body 的 `mode` 字段区分 4 种工作模式，复用同一个 `/api/v1/chat/completions` 端点。

**理由**：改动最小（前端加一个字段 + 后端加一个路由器），完全向后兼容（mode 默认 `"data"`）。无需新增路由，SSE 管道和任务清单机制完全复用。

### ADR-002：JSON 文件 + watchdog 热更新

**决策**：配置存储采用 JSON 文件（`backend/configs/`），通过 watchdog 监听文件变更实现热更新。

**理由**：参考 ClaudeCode/CodeBuddy 的 CLI 配置模式（用户直接编辑 JSON 文件即可）。相比 Redis/数据库方案，JSON 文件便于版本控制（git diff）、手动编辑和迁移。watchdog 是 Python 标准工具，轻量可靠。

### ADR-003：Element Plus 用于管理页

**决策**：管理页面（LLM/Skill/MCP/知识库/定时任务）使用 Element Plus，聊天页面保持纯 CSS。

**理由**：管理类页面需要大量表格/表单/对话框/开关组件，Element Plus 开箱即用。聊天 UI 已精调，保持沉静风格不变。两者通过 Vue Router 页面隔离，互不干扰。

### ADR-004：研究报告模式 A→C 演进

**决策**：阶段 7 先实现纯 RAG 报告模式（A），阶段 9 升级为 RAG+数据混合模式（C）。

**理由**：混合模式依赖完整 RAG 系统（阶段 9），分阶段交付可尽早验证报告模式可行性，同时不阻塞 RAG 系统的独立建设。

## 4. 数据模型

### chat_sessions 表扩展

```sql
ALTER TABLE chat_sessions ADD COLUMN mode VARCHAR(20) DEFAULT 'data';
-- 值: data / report / doc / task
```

### 新增知识库表（阶段 9）

```sql
CREATE TABLE knowledge_bases (
    id VARCHAR(36) PRIMARY KEY,
    user_id VARCHAR(50) NOT NULL,
    name VARCHAR(200) NOT NULL,
    file_name VARCHAR(200) NOT NULL,
    file_size BIGINT NOT NULL,
    chunk_count INT DEFAULT 0,
    milvus_collection VARCHAR(100),
    status ENUM('uploading','processing','ready','failed') DEFAULT 'uploading',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

### 新增定时任务表（阶段 10）

```sql
CREATE TABLE scheduled_tasks (
    id VARCHAR(36) PRIMARY KEY,
    user_id VARCHAR(50) NOT NULL,
    name VARCHAR(200) NOT NULL,
    cron_expression VARCHAR(50) NOT NULL,
    task_prompt TEXT NOT NULL,
    mode VARCHAR(20) DEFAULT 'data',
    enabled TINYINT(1) DEFAULT 1,
    last_run_at DATETIME,
    next_run_at DATETIME,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

## 5. 兼容性约束

| 约束项 | 要求 |
|--------|------|
| API 兼容 | 不传 `mode` 时默认走 `data` 模式，现有所有调用零改动 |
| SSE 兼容 | 复用现有 14 种 SSE 事件类型，新增模式不引入新事件类型 |
| 数据库兼容 | `chat_sessions.mode` 默认值 `data`，无需迁移已有数据 |
| 前端兼容 | 聊天页保持纯 CSS，Element Plus 仅在管理页按需引入 |
| 配置兼容 | 现有 `.env` 中的 LLM 配置自动迁移为默认 LLM Provider |
