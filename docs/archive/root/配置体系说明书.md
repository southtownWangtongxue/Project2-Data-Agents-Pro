> **参考标准**: ClaudeCode/CodeBuddy CLI 配置模式  
> **版本**: V2.0  
> **日期**: 2026-07-02

---

## 1. 设计理念

参考 ClaudeCode (`~/.claude/claude_desktop_config.json`) 和 CodeBuddy 的 JSON 配置文件管理模式，DataAgent Pro V2.0 采用**声明式 JSON 配置** + **文件监听热更新**。用户直接编辑 JSON 文件即可完成配置变更，无需重启服务。

### 核心理念

- **文件即配置**：所有配置以 JSON 文件存储于 `backend/configs/` 目录
- **即时生效**：watchdog 监听文件变更 → 自动重载 → 下一次 API 请求使用新配置
- **版本可控**：JSON 文件可纳入 Git，配置变更有迹可循
- **校验安全**：重载时 JSON Schema 验证 + 降级兜底（损坏时使用上次有效缓存）

## 3. LLM 模型配置 (llm_providers.json)

### 配置结构

```json
{
  "providers": [
    {
      "id": "qwen-default",
      "name": "Qwen-Max（默认）",
      "api_base": "https://dashscope.aliyuncs.com/compatible-mode/v1",
      "api_key_env": "DASHSCOPE_API_KEY",
      "model": "qwen-max",
      "temperature": 0.3,
      "max_tokens": 4096,
      "timeout": 60,
      "max_retries": 2,
      "is_default": true,
      "enabled": true
    }
  ],
  "mode_defaults": {
    "data": "qwen-default",
    "report": "qwen-default",
    "doc": "qwen-default",
    "task": "qwen-default"
  }
}
```

### 字段说明

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | string | ✅ | 唯一标识，用于 `mode_defaults` 映射 |
| `name` | string | ✅ | 显示名称（前端下拉框展示） |
| `api_base` | string | ✅ | 兼容 OpenAI 协议的 API 地址 |
| `api_key_env` | string | ✅ | API Key 所在的环境变量名（如 `DASHSCOPE_API_KEY`） |
| `model` | string | ✅ | 模型名称（传给 API 的 model 参数） |
| `temperature` | float | ❌ | 温度参数，默认 0.3 |
| `max_tokens` | int | ❌ | 最大输出 Token，默认 4096 |
| `timeout` | int | ❌ | 请求超时时间（秒），默认 60 |
| `max_retries` | int | ❌ | 最大重试次数，默认 2 |
| `is_default` | bool | ❌ | 是否全局默认模型（有且仅有一个为 true） |
| `enabled` | bool | ❌ | 是否启用（false 时前端不显示） |

### mode_defaults

- 各模式可指定不同默认模型
- 用户在对话中可覆盖（前端下拉切换）
- `task` 模式（通用 Agent）建议使用推理能力强的模型

### 示例：添加 DeepSeek 模型

```bash
# 1. 编辑配置文件
vim backend/configs/llm_providers.json
```

```json
{
  "providers": [
    // ... 保留原有配置 ...
    {
      "id": "deepseek-v3",
      "name": "DeepSeek-V3",
      "api_base": "https://api.deepseek.com/v1",
      "api_key_env": "DEEPSEEK_API_KEY",
      "model": "deepseek-chat",
      "temperature": 0.0,
      "max_tokens": 8192,
      "timeout": 60,
      "max_retries": 3,
      "is_default": false,
      "enabled": true
    }
  ],
  "mode_defaults": {
    "data": "qwen-default",
    "report": "deepseek-v3",
    "doc": "qwen-default",
    "task": "deepseek-v3"
  }
}
```

```bash
# 2. 设置 API Key
export DEEPSEEK_API_KEY="sk-xxxx"

# 3. 保存文件即生效（watchdog 自动检测 → 重载 → 下次请求使用新模型）
```

### 字段说明

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | string | ✅ | 唯一标识 |
| `name` | string | ✅ | 显示名称 |
| `description` | string | ✅ | 功能说明（Tooltip 展示） |
| `icon` | string | ❌ | 图标名（前端图标映射） |
| `enabled` | bool | ✅ | 是否启用 |
| `modes` | string[] | ✅ | 所属模式（当前 skill 在哪些模式下可用） |
| `params` | object | ❌ | 参数配置（key-value） |

### Skill 加载规则

- 每个请求根据 `mode` 参数，只加载 `modes` 包含该模式的已启用 Skill
- Skill 的 `params` 传递给对应的 LangChain Tool 初始化函数
- 通过 `DynamicRegistry` 在每次 `astream` 时动态绑定

## 5. MCP 服务器配置 (mcp_servers.json)

### 配置结构

```json
{
  "servers": [
    {
      "id": "filesystem",
      "name": "文件系统",
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/tmp"],
      "enabled": false,
      "check_interval": 30
    },
    {
      "id": "postgres",
      "name": "PostgreSQL MCP",
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-postgres", "postgresql://localhost/mydb"],
      "enabled": false,
      "check_interval": 60
    },
    {
      "id": "brave-search",
      "name": "Brave Search",
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-brave-search"],
      "env": { "BRAVE_API_KEY": "${BRAVE_API_KEY}" },
      "enabled": false,
      "check_interval": 30
    }
  ]
}
```

### 字段说明

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | string | ✅ | 唯一标识 |
| `name` | string | ✅ | 显示名称 |
| `command` | string | ✅ | 启动命令（如 `npx`、`uvx`、`python`） |
| `args` | string[] | ✅ | 命令参数 |
| `env` | object | ❌ | 环境变量（支持 `${ENV_VAR}` 占位符） |
| `enabled` | bool | ✅ | 是否启用 |
| `check_interval` | int | ❌ | 连通性检测间隔（秒），默认 30 |

### 状态检测

```
定时任务 (每 check_interval 秒)
  → 尝试连接 MCP Server (stdio transport)
  → 成功: 🟢 online
  → 失败: 🔴 offline (记录错误日志)
  → 未检测: ⚪ unknown (新建未测试)
```

## 6. 默认配置 (default.json)

### 配置结构

```json
{
  "default_mode": "data",
  "default_model": "qwen-default",
  "stream_enabled": true,
  "max_clarifier_count": 2,
  "quality_gate_max_retries": 2,
  "suggestions_count": 5,
  "suggestions_timeout": 8
}
```

### 字段说明

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `default_mode` | string | `data` | 未指定 mode 时的默认模式 |
| `default_model` | string | 第一个 LLM | 全局默认模型 |
| `stream_enabled` | bool | `true` | 是否启用 SSE 流式输出 |
| `max_clarifier_count` | int | `2` | Clarifier 最大追问次数 |
| `quality_gate_max_retries` | int | `2` | ReAct 质量门最大重试次数 |
| `suggestions_count` | int | `5` | 问题建议生成数量 |
| `suggestions_timeout` | int | `8` | 问题建议 API 超时时间（秒） |

## 7. 热更新机制

### 流程图

```
用户编辑 JSON 文件（vim / 前端管理页） 
  → 保存文件
  → watchdog (inotify/ReadDirectoryChangesW) 检测到 FILE_MODIFIED 事件
  → 防抖 500ms（避免连续保存触发多次重载）
  → ConfigManager.reload()
    ├── 读取文件内容
    ├── JSON Schema 校验
    ├── 校验通过 → 更新内存配置缓存
    └── 校验失败 → 保留旧缓存 + 记录 error 日志
  → 下一次 /api/v1/chat/completions 请求
    → DynamicRegistry 从 ConfigManager 缓存获取最新配置
    → 构造 LLM Client + Tools → astream
```

### 降级策略

| 场景 | 行为 |
|------|------|
| JSON 格式错误 | 保留上次有效配置，日志记录错误详情 |
| Schema 校验失败 | 保留上次有效配置，日志记录校验结果 |
| 文件不存在 | 使用代码内置默认配置 |
| API Key 失效 | 运行时返回错误给前端，不影响其他模型 |

### 前端管理页同步

- 前端管理页修改配置 → 调用 API `POST /api/v1/config/update` → 后端写入 JSON 文件
- 同时支持直接编辑 JSON 文件和前端 UI 操作，两者等效
- 前端操作后即时生效（API 写入文件 → watchdog 触发重载 → 同一请求周期内生效）

## 8. JSON Schema 校验

### llm_providers.schema.json（示例）

```json
{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "type": "object",
  "required": ["providers", "mode_defaults"],
  "properties": {
    "providers": {
      "type": "array",
      "items": {
        "type": "object",
        "required": ["id", "name", "api_base", "api_key_env", "model"],
        "properties": {
          "id": { "type": "string", "pattern": "^[a-z0-9_-]+$" },
          "name": { "type": "string", "minLength": 1 },
          "api_base": { "type": "string", "format": "uri" },
          "api_key_env": { "type": "string", "minLength": 1 },
          "model": { "type": "string", "minLength": 1 },
          "temperature": { "type": "number", "minimum": 0, "maximum": 2 },
          "max_tokens": { "type": "integer", "minimum": 1 },
          "timeout": { "type": "integer", "minimum": 1 },
          "max_retries": { "type": "integer", "minimum": 0 },
          "is_default": { "type": "boolean" },
          "enabled": { "type": "boolean" }
        }
      }
    },
    "mode_defaults": {
      "type": "object",
      "properties": {
        "data": { "type": "string" },
        "report": { "type": "string" },
        "doc": { "type": "string" },
        "task": { "type": "string" }
      }
    }
  }
}
```

## 9. 与 ClaudeCode/CodeBuddy 的对比

| 维度 | ClaudeCode | CodeBuddy | DataAgent Pro V2.0 |
|------|-----------|-----------|-------------------|
| 配置文件 | `claude_desktop_config.json` | `.codebuddy/settings.json` | `backend/configs/*.json` |
| LLM 配置 | `providers` 数组 | `providers` 数组 | `providers` 数组 |
| MCP 配置 | `mcpServers` | `mcpServers` | `mcp_servers.json` |
| Skill 管理 | 内置 tools | 内置 skills | `skills.json` + 前端卡片管理 |
| 热更新 | 重启 Claude Desktop | 重启 IDE | **watchdog 自动热更新，无需重启** |
| 多模式 | 单一对话模式 | 单一对话模式 | 4 种工作模式 + 每模式独立默认模型 |
| 校验 | 无 | 无 | **JSON Schema 校验 + 降级兜底** |
