### 2.3 关键链路缺陷：默认模型路由回退（追加发现）

**现象**：不传 `model` 时，全部 LLM 调用返回 `403 Free quota exhausted`。

**根因链**：

```
ChatRequest.model = None
  → get_config_manager().get_llm_config(None)
  → 返回 None（llm_providers.json 中无任何 provider 标记 is_default）
  → set_provider(None)
  → 静默回退 .env 的 LLM_BASE_URL = DashScope（免费额度已耗尽）
  → 403，SQL 生成失败，流程降级走 rag_agent 直接 finish
```

**次生缺陷**：`chat.py:_resolve_enabled_provider()` 的兜底分支遍历 `cm.providers`，而 `ConfigManager` 实际属性为 `llm_providers`，`getattr(cm, "providers", None)` 恒为 `None` → **该兜底逻辑为死代码，永不生效**。

**验证**：显式传 `model=agnes` 后，同一问题完整跑通 291 个 SSE 事件，`sql → security → execute → result → analyst → token` 全链路正常。

## 五、测试结论

1. **可用**：认证鉴权主体、SSE 协议完整性、会话管理、配置中心、数据脱敏、系统提示词分层组装——六个方面表现稳定，可作为后续演进基线。
2. **必须立即修复**：DEF-001 ~ DEF-004 四项 P0。其中 **DEF-003（SQL 分类绕过）直接击穿"改数据必批"这一核心安全承诺**，DEF-004 使 MCP 能力实际不可用。
3. **架构性缺陷**：DEF-005 暴露「配置层（前端可见的 enabled provider）」与「运行时层（.env 环境变量）」存在**双轨且不一致**的路由机制，建议统一为单一真相源。
4. **可观测性**：事件溯源基础设施已建成（`event_sourcing.py`、`trajectory`、`export`），但默认关闭，导致"每次运行都能回看"的能力实际未交付。
5. **性能**：42s 的端到端时延与 <5s 的目标存在数量级差距，需在功能补齐后专项治理。

## 八、2026-09-10 非管理员权限回归（RBAC，补齐 TC-CFG-07）

> 09-03 轮次因「系统仅有 admin 账号」将 TC-CFG-07 判为阻塞；本轮使用非管理员账号 `165019`（`user_type=01`）完成验证。

### 8.1 现象

非管理员登录后进入配置中心，LLM 模型 / Skill 技能 / MCP 服务三页报「加载失败」且列表为空，控制台出现 `403 (Forbidden)` 与 `[API Error] [object Object]`。

### 8.2 根因

| # | 层面 | 根因 |
|---|------|------|
| RC-1 | 前端权限 | `stores/auth.ts` **已实现 `isAdmin`（`user_type==='00'`）但前端从未消费**：App 导航、路由、`AdminLayout` 侧栏均无权限分流，非管理员可进入 `/admin/*`；而这三类页面调用的 `/config/*` 被后端 `require_admin` 返回 403 |
| RC-2 | 错误处理 | 页面 `catch` 统一 `ElMessage.error('加载失败')`，未区分「权限不足」；`client.ts` 把错误对象直接打印，输出 `[object Object]`，排查困难 |
| RC-3 | 权限模型 | 后端权限并不一致：`/config/*` 仅管理员，而 `/knowledge/*`、`/schedule/*` 对全员开放；前端未体现该差异，导致「一刀切」感知 |

### 8.3 修复（按后端开放度区分，已确认口径）

| 文件 | 修改 |
|------|------|
| `api/client.ts` | 新增 `getApiErrorMessage(error, fallback)`：归一化 `detail` 字符串 / 422 数组 / 对象；响应拦截器日志改用该函数，消除 `[object Object]` |
| `router/index.ts` | 三个管理员页签加 `meta.requiresAdmin`；守卫拦截非管理员 → 提示「该页面仅管理员可访问，已跳转至知识库」并跳转 `/admin/knowledge`；`/admin` 默认落地页按角色分流（管理员 → `/admin/llm`，非管理员 → `/admin/knowledge`） |
| `router/index.ts` | 角色判定改为**解析 localStorage 中的 JWT**（`isAdminUser()`），不依赖 pinia |
| `views/AdminLayout.vue` | 菜单项增加 `adminOnly` 标记，非管理员仅渲染「知识库 / 定时任务」 |
| `views/admin/{Llm,Skill,Mcp}Config.vue` | `catch` 改用 `getApiErrorMessage(e, '加载失败')`，403 时展示后端返回的「需要管理员权限」 |

**连带修复**：初版在函数式 `redirect` 中调用 `useAuthStore()`，因路由安装早于 `app.use(pinia)` 而抛 `getActivePinia()` 异常，导致 `/admin` **整页空白**；改为 JWT 解析后消除。
