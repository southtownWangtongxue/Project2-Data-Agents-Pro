## 三问题+两遗留修复完成（2026-08-19，浏览器实测全部通过）
设计文档 `docs/plans/2026-08-19-issues-fix-design.md`。

### 问题1：14天前会话无法加载 → 已修
根因：`session_events` 事件溯源 8/17 才启用（旧会话无事件）+ Redis checkpoint TTL 7 天已过期 → 两者皆空。
修复：`chat.py` `get_session_messages` 末尾加兜底——事件与 Redis 均空时从 `chat_nodes.question` 构建最低限度消息（对齐 Harness 永不丢失会话）。
验证：14 天前会话「帮我分析一下数据库中有哪些数据」加载出 2 条 text 消息（用户问题+助手回复）✓。

### 问题2：工具渲染混乱 → 已修
根因：`toolInfo` label 有「调用:/完成:」前缀+icon 跳变（🔧→🔗）；`formatToolMeta` 拼接所有字段；`toolExpandContent` 只处理 input/result/info/sql，reporter 的 chart_type/execute_sql 的 row_count 展开为空。
修复（`Chat.vue`）：`toolInfo` 统一 `🔧 工具名`；`formatToolMeta` 单行摘要（优先 result/status/input/info）；`toolExpandContent` 统一遍历 toolMeta 全部字段（labelMap 友好命名），无 meta 时特判 execute_sql/sql_coder/analyst 从关联消息推导。
验证：`🔧 execute_sql 返回 5 条记录`、`🔧 misc_agent { "question": ... }` 单行折叠 ✓。

### 问题3：切换会话工具卡片消失 → 已修
根因：`_project()` 不投影 tool_chain（过程态事件）；传统模式（非 DeepAgent）工具事件不落库 TOOL_CHAIN。
修复：
- `event_sourcing.py` `_project()`：新增 TOOL_CHAIN 投影（toolName 取 payload.name/tool_name，result 取 payload.result/content）。
- `chat.py` `_stream_chat`：misc_agent（两分支）/execute_sql/reporter 补 `_track(EventType.TOOL_CHAIN, ...)`。
验证：新会话事件日志 tool_chain=2；derive_messages 投影 tool_chain=2（execute_sql/reporter）；切换会话后 UI 渲染 `🔧 execute_sql 返回 5 条记录`、`🔧 reporter 生成 pie 图表` ✓。

### 遗留1：misc_agent 双重推送 → 已修
根因：`misc_agent()` 内部已 StreamContext.push_token 逐 token 推送，`chat.py` misc_agent 分支又 `_stream_tokens(content)` 二次流式 → 重复推送、loading 感知翻倍。
修复：有 analysis_text 时不再二次 `_stream_tokens`（仅 messages 兼容分支保留流式）。
注意：首轮响应整体耗时（首token 26-60s）仍主要受模型本身延迟影响，非代码缺陷。

### 遗留2：新建/切换会话输入框未聚焦 → 已修
修复：`ChatInput.vue` onMounted 加 `nextTick(focus())`；`Chat.vue` ChatInput 绑 `:key="store.currentThreadId || 'new'"`（新建/切换重建触发聚焦）。
验证：新建会话后输入框 `focused` ✓。
