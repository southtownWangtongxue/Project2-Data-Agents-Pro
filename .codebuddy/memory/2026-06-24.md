# 2026-06-24 工作日志

## Phase E.7 — 动态问题建议（基于表结构）

### 背景
前端 Chat.vue 空状态页面有三个硬编码的问题模板：「查询本月销售额Top10产品」「分析用户增长趋势」「查看各地区营收占比」。这些问题与用户的实际表结构不相关，导致生成结果不理想。

### 实现方案
1. **新建 Agent** `backend/app/agents/question_suggester.py`：
   - 接收表结构文本，调用 LLM 生成 3-5 条基于实际表结构的自然语言问题
   - 使用 `temperature=0.7` 保证问题多样化
   - 支持 JSON 解析 + 降级按行提取
   - 模块级 in-memory 缓存（基于 schema hash），表结构不变时复用

2. **新增 API** `GET /api/v1/chat/suggestions`（在 `chat.py` 中）：
   - 连接数据库 → 加载全部表结构 → 调用 question_suggester agent → 返回 JSON
   - 支持 `?force_refresh=true` 强制刷新缓存
   - 需要 Bearer token 认证

3. **前端修改**：
   - `chat.ts` store: 新增 `suggestions`、`suggestionsLoading` 状态 + `loadSuggestions()` 方法
   - `Chat.vue`: `onMounted` 时调用 `store.loadSuggestions()`，空状态使用动态问题
   - 三种状态：正常显示 / 骨架屏加载 / API 失败兜底
   - 新增刷新按钮（旋转动画），点击重新生成建议

### 关键文件
- `backend/app/agents/question_suggester.py` — 新建
- `backend/app/api/v1/chat.py` — 新增 imports + GET /suggestions 端点
- `frontend/src/stores/chat.ts` — 新增 suggestions 状态 + loadSuggestions 方法
- `frontend/src/views/Chat.vue` — 硬编码问题 → 动态问题模板

## Phase E.9 — ReAct 质量门（结果质量评估改造）

### 背景
工作流缺少对查询结果质量的评估。典型案例：用户问"查询本月销售额Top10产品"，SQL 返回仅 1 行数据，但流程仍走到 Analyst → Reporter 生成无意义的柱状图。当前路由只用简单的 `if query_result:` 做非空判断，没有质量评估。

### 改造方案
按 ReAct (Reason + Act) 范式，在两个关键决策点引入 LLM 质量评估：

**1. QualityGate 节点（execute_sql → quality_gate → analyst）**
- 新建 `backend/app/agents/quality_evaluator.py`：`evaluate_query_quality()` 用 LLM 评估结果是否充分回答了用户问题
- 评估标准：数据量是否合理（Top10 应返回 ~10 行，仅 1 行则 insufficient）、数值是否有意义、是否与问题预期匹配
- 返回 `quality`（good/insufficient/empty）+ `reason` + `feedback`（用户友好的中文说明）
- 质量不足时路由到 misc_agent（降级），质量好时路由到 analyst

**2. Analyst 动态 chart_suitable**
- 修改 `analyst.py`：LLM 分析结果中新增 `chart_suitable` 字段，同一 LLM 调用完成数据分析和图表适配性判断
- 修改 `analyst_node`：使用 LLM 返回的 `chart_suitable` 设置 `dynamic_chart_suitable`
- 修改 `route_analyst`：优先使用 `dynamic_chart_suitable`，回退到 Planner 的静态判断

**3. 新增状态字段** (`state.py`)
- `query_quality`: "good"|"insufficient"|"empty"
- `quality_feedback`: 用户友好的质量说明文本
- `dynamic_chart_suitable`: Analyst 基于实际数据的动态图表判断

**4. SSE 事件** (`chat.py`)
- 新增 `quality_gate` 节点事件处理，推送质量评估状态和反馈

### 新的工作流
```
execute_sql
  ├── 空结果 → misc_agent（降级）
  └── 有结果 → quality_gate（ReAct质量门）
                  ├── good → analyst → dynamic_chart_suitable?
                  │               ├── true → reporter → finish
                  │               └── false → answer → finish
                  └── insufficient/empty → misc_agent（带质量反馈）
```

### 关键文件
- `backend/app/agents/quality_evaluator.py` — 新建，LLM 质量评估器
- `backend/app/graph/state.py` — 新增 3 个 ReAct 相关字段
- `backend/app/graph/workflow.py` — 新增 quality_gate_node + route_quality_gate，修改 route_execute/analyst_node/route_analyst
- `backend/app/api/v1/chat.py` — 新增 quality_gate SSE 事件处理
- `backend/app/agents/analyst.py` — LLM 输出中新增 chart_suitable 字段

## 修复: quality_evaluator.py SyntaxError

### 问题
启动报错 `SyntaxError: invalid syntax. Perhaps you forgot a comma?` 在 `quality_evaluator.py` 第90行。

### 原因
中文弯引号 `""`（U+201C/U+201D）在 `write_to_file` 写入时被存成了 ASCII 双引号 `"`，导致Python将字符串中间的引号误解为字符串终止符。涉及行：98-100（如 `"Top10"`、`"趋势分析"`、`"排名"`）和108（`"建议扩大时间范围"`）。

### 修复
将所有中文引号替换为「」书名号，避免与 Python 字符串分隔符冲突。

## 修复: 会话历史列表不自动更新

### 问题
一轮会话结束时，后端成功保存标题（日志 `[TitleGen] 标题已保存`），但前端侧边栏仍然显示"无会话记录"。

### 原因
`chat.ts` 的 `onDone` 回调（SSE 流结束时）只设置了 `isLoading = false`，没有调用 `loadSessions()` 重新拉取会话列表。`loadSessions()` 仅在 `Chat.vue` 的 `onMounted` 时调用一次。

### 修复
在 `frontend/src/stores/chat.ts` 第297行 `onDone()` 中添加 `loadSessions()` 调用，SSE 流结束后自动刷新侧边栏会话列表。

## 修复: thread_id 复用 + 多轮对话导航

### 问题
1. 同一会话中每次发消息都生成新的 `thread_id`，导致侧边栏出现多条独立会话
2. 多轮对话缺少轮次间的快速跳转

### 方案: 解耦 session_id (MySQL) 和 run_id (Redis)

**核心原理**: session thread_id 用于 MySQL 分组（多轮复用），run_id 用于 LangGraph Redis checkpointer（每次新建），避免 checkpoint 状态冲突。

### 后端改动
1. **`session.py`**: `ChatNode` 模型新增 `run_id` 字段（用于 Redis checkpoint 恢复）
2. **`chat.py` ChatRequest**: 新增 `thread_id: str | None = None` 字段
3. **`chat.py` _stream_chat**: 接受 `existing_thread_id`，生成 `session_thread_id`（复用或新建）+ `run_id`（每次新建）；新增 `_count_nodes()` 计算已有节点数
4. **`chat.py` _stream_chat_deepagent**: 同样改动
5. **`chat.py` _save_chat_node**: 新增 `run_id` 参数，存入 MySQL
6. **`chat.py` get_session_messages**: 用 `chat_nodes.run_id` 查询 Redis（回退到 thread_id 兼容旧数据）
7. **`chat.py` chat_completions**: 传递 `body.thread_id`

### 前端改动
1. **`chat.ts` sendMessage**: 请求体新增 `thread_id: currentThreadId.value || undefined`
2. **`chat.ts`**: 新增 `turns`、`currentTurnIndex`、`loadSessionNodes()`；`onDone` 中调用 `loadSessionNodes()`
3. **`Chat.vue`**: v-for 改为 `<template>` 包裹以插入 `NodeSeparator`；工具栏新增节点导航 chip（`node-nav`）；新增 `hasSeparatorBefore()`、`scrollToNode()` 函数
