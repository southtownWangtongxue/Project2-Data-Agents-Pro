## 前端 Docker 构建失败修复（TypeScript 编译错误，11 处）

### 背景
GitHub Actions 的 `npm run build`（`vue-tsc && vite build`）失败，共 11 处 TS 错误。已全部修复，本地 `vue-tsc --noEmit` + `npm run build` 通过（dist 产物时间戳 2026-08-13 10:41）。

### 修复清单（11 个文件）
1. **`api/client.ts`（根因修复）**：响应拦截器运行时 `return response.data` 解包，但 `client` 类型是 `AxiosInstance`（TS 类型层面返回 `AxiosResponse`）→ 所有访问 `.documents/.providers/.skills/.servers/.tasks/.mode_defaults` 报 TS2339。修复：导出 `DataApiClient` 接口（`get/post/put/patch/delete` 返回 `Promise<T>`），`export default client as unknown as DataApiClient`。一处修复解决 9 处 AxiosResponse 错误（chat.ts + KnowledgeConfig + LlmConfig + McpConfig + ScheduleConfig + SkillConfig）。
2. **`ModeBar.vue`**：`modes` 数组缺 `disabled` 属性，但 `selectMode`/模板引用 `m.disabled`（TS2339）→ 每个元素补 `disabled: false`。
3. **`useSSE.ts`**：`doneReceived` 在 `connect` 函数内声明却被独立函数 `dispatchEvent` 引用（TS2304）→ 提升到 `useSSE()` 作用域，`connect` 里重置；`event.label` 不存在（TS2339）→ `SSEEventData` 接口补 `label?: string`。
4. **`chat.ts`**：`messages.value.findLastIndex()` 是 ES2023 API，tsconfig lib=ES2020 报 TS2550 → 改用 for 循环倒序查找。
5. **`router/index.ts`**：删未使用 import `useAuthStore`（TS6133）。
6. **`stores/auth.ts`**：删未使用 import `AxiosError`（TS6133）。
7. **`ClarifierCard.vue`**：`const props = defineProps()` 但未使用 → 改 `defineProps()` 不赋值（模板直接用 msg）。
8. **`MessageRenderer.vue`**：删未使用函数 `formatToolMeta`（TS6133）。
9. **`Approval.vue`**：删未使用函数 `shortQuestion`（TS6133）。
10. **`LlmConfig.vue`**：删未使用 `formRef`/`formRules` 及 `FormInstance` 类型导入（TS6133）。
11. **`XConversations.vue`**：menu `onClick` 参数类型 `{ key: string }` 与 `MenuClickEventHandler` 的 `MenuInfo`（key 是 `Key`=string|number）不兼容（TS2322）→ 改 `{ key: string | number }`。

### 关键教训
- **本地 node_modules 是 2026-04-29 的旧版本**，与 Docker `npm ci`（按 package-lock）的版本不一致，导致本地验证结果可能失真。
- **Windows cmd 下 vue-tsc 的报错输出会被 execute_command 的 stdout 缓冲吞掉**（看似 exit 0 无输出实则有错）。必须用文件重定向 `vue-tsc --noEmit > log.txt 2>&1` 再读文件才能拿到真实错误。
- **用户粘贴的另一个 AI 分析有误**：其建议把 `data.documents` 改成 `res.data.documents` 是错的——拦截器已解包，运行时 `res.data` 会是 undefined。正确做法是修 client 类型而非改调用处。
